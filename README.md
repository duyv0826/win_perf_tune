# Windows 性能优化脚本（win_perf_tune.ps1）

一个 Windows 10/11「安全清理 + 前后指标对比」演示脚本，设计原则：**只读优先、写操作可控、可回滚、高危项默认关闭**。

## 运行方式

```powershell
# 预演（不做任何修改，推荐先看）
.\win_perf_tune.ps1 -WhatIf

# 默认安全运行（建还原点 + 安全清理，高危项跳过）
.\win_perf_tune.ps1

# 仅当已知风险并需要时，才启用高危优化
.\win_perf_tune.ps1 -ApplyRisky
```

> 建议以**管理员**身份运行以获得完整功能（系统还原点、DISM 组件清理均需提权）。
> 非管理员会话下脚本不会崩溃：需提权的步骤会告警并跳过，其余清理照常。

## 参数

| 参数 | 说明 |
|---|---|
| `-WhatIf` | 预演模式：仅报告将执行的操作，不修改任何内容 |
| `-ApplyRisky` | 启用高危优化（禁用启动项 / 服务优化 / 虚拟内存）；**默认关闭** |
| `-SkipRestorePoint` | 跳过创建系统还原点（不推荐） |

## 执行流程

1. 创建系统还原点（回滚基线；需管理员，失败仅告警不阻断）
2. 只读采集「优化前」指标
3. **安全清理**（默认执行）：刷新 DNS 缓存 → 清理用户临时文件 → 清空回收站 → DISM 更新组件清理
4. **高危优化**（默认跳过，仅 `-ApplyRisky` 启用，逐项处理且不 Disable 关键服务）
5. 采集「优化后」指标并输出控制台对比表

## `-ApplyRisky` 为何默认关闭

| 高危项 | 风险 |
|---|---|
| 禁用启动项 | 误禁可能破坏登录、驱动自启、安全软件/云同步 |
| 修改系统服务 | 改错服务会让网络/音频/打印等静默失效 |
| 调整虚拟内存 | 改 pagefile 易致蓝屏、应用崩溃、休眠失败，收益不确定 |

因「收益不确定、代价高」，三项默认关闭；即便 `-ApplyRisky`，脚本也只把明确可延迟的
非关键服务设为 `Manual`，**绝不 Disable 关键服务**。

## 虚拟内存说明

脚本**不自动调整虚拟内存**，仅打印提示。如需调整，请手动操作：
> 设置 → 系统 → 关于 → 高级系统设置 →「性能」区「设置」→ 高级 → 虚拟内存「更改」
> → 取消「自动管理」→ 按需设固定值 → 确定并**重启生效**。

## 测试（Pester）

仓库附 `win_perf_tune.Tests.ps1`，使用 **Pester 6.x** 对 PowerShell 版做单元/集成测试，覆盖：

- **管理员权限校验**：非管理员时不中断；管理员时仍创建还原点
- **还原点创建逻辑**（`New-RestorePoint`）：成功返回 `$true` 并调用封装函数、失败被捕获返回 `$false`、WhatIf 不调用且不报错
- **清理操作成败路径**：四步安全清理均被调用；`Remove-Item` / `Clear-RecycleBin` 抛错时被捕获、主流程继续
- **异常边界**：`Get-Counter` 不可用回落默认值；还原点创建失败主流程仍完成
- **`-ApplyRisky` 分支**：默认不调用、启用时调用
- **退出码**：脚本以 `exit 0` 收尾；直接 `-WhatIf` 运行进程退出码为 `0`（不泄漏 740）

运行（需 Pester 6.x）：

```powershell
Install-Module Pester -Scope CurrentUser -Force   # 首次安装
Invoke-Pester -Path .\win_perf_tune.Tests.ps1
```

> 若本机同时存在系统目录下的 Pester 3.x（Windows 自带），请先隔离模块路径仅保留 6.x
> 所在用户模块目录，避免 `Mock` / `Should` 命令被旧版解析：
> ```powershell
> $env:PSModulePath = "$HOME\Documents\WindowsPowerShell\Modules" + ';' + ($env:PSModulePath -split ';' | Where-Object { $_ -and $_ -notmatch 'Program Files\\WindowsPowerShell\\Modules' }) -join ';'
> Import-Module Pester -RequiredVersion 6.0.1 -Force
> Invoke-Pester -Path .\win_perf_tune.Tests.ps1
> ```

> 设计说明：`New-RestorePoint` 内部经由 `Invoke-CheckpointComputer` 薄封装调用 `Checkpoint-Computer`，
> 因后者在本环境解析为 **Alias** 会遮蔽 Pester 的 mock，测试统一 mock 该封装函数来保证稳定拦截。
> 封装不改变任何运行时行为。

**实测要点**

- **还原点创建并验证链路通过**：标准运行打印 `[+] 还原点已创建并验证`，证明 `Invoke-CheckpointComputer` → `Checkpoint-Computer` → 验证 整条链路在管理员会话真实可用。
- **C 盘真实释放约 5.18 GB**（161.19 → 166.37），来自 DISM 更新组件清理 + 用户临时文件清理，是本次唯一确定性的「优化直接收益」；其余指标（CPU / 内存 / 服务数）均为系统负载波动，非优化直接结果。
- **24 小时还原点限流（重要）**：Windows 默认每 1440 分钟（24 小时）只允许新建一个还原点。第 ② 次运行距第 ① 次仅约 2 分钟，故被系统拒绝新建；脚本**优雅降级**为 `还原点创建请求已提交（验证信息暂不可用）`，高危优化仍继续执行。
  - 含义：若一天内多次运行，**只有当天首次**会真正「创建并验证」新还原点；后续运行的回滚基线仍是当天首个还原点（仍有效）。
  - 建议：把 `-ApplyRisky`（不可逆风险最高）放在**当天首次运行**，或先人工确认已存在可用还原点，再执行高危分支。
- **DNS 缓存条目**在 `flushdns` 后会被网络活动立即重新填充，甚至归零/翻倍均属正常，不代表清理失败。
- **`-ApplyRisky` 仅**把 `DiagTrack` / `SysMain` 设为 `Manual`，**未 Disable 任何关键服务**，也**未触碰虚拟内存**（符合设计）。

> ⚠️ 真实管理员运行会执行：创建系统还原点（并验证）、刷新 DNS、清理 `%TEMP%`、清空回收站、DISM 组件清理。
> 其中**清空回收站为不可逆操作**，请确认回收站内无需要保留的文件后再运行（不加 `-WhatIf` 的版本）。
> 若当天已运行过，再次创建还原点会被 Windows 限流（见上「24 小时还原点限流」），属预期行为。
